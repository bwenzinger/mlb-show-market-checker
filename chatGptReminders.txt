- `src/components/market/MarketDetail.tsx` imports shared components from `./common`.

- Verification after the split:
  - `npm run typecheck` passed.
  - `npm run build` passed.
- `src/components/market/common/useQueryParams.ts` was changed from a local shallow-stable ref helper into a shared URL query-param store.
- The hook now uses `useSyncExternalStore`, listens for `popstate`, patches `history.pushState` and `history.replaceState`, and returns stable params plus `setQueryParams`.
- The hook only changes the returned params reference when the shallow key/value shape of the URL params changes.
- `useQueryParams` and `updateQueryParams` now support a generic param shape so reads and updates can be typed by query-param keys.
- `src/components/market/SearchPanel.tsx` now uses a custom fixed-row virtualized list instead of rendering every market listing row at once.
- The search list virtualization uses a local scroll container, fixed row height, and overscan. It does not auto-scroll to the selected item; sort/filter/search changes reset the list scroll position to the top.
- `src/marketUtils.ts` now passes `itemType` and `rarity` through to the paginated listings fetch so the app can reduce API requests when those filters are set.
- When `itemType` is selected, market fetching now only requests that one type instead of all market item types.
- `SearchPanel` now includes post-query price filters for min/max buy now and min/max sell now.
- The new price filters are URL-backed query params and are applied locally in `fetchSortedListings` after the API response is received.
- The post-query price filters now always live behind a `Filters` button in `SearchPanel`, which opens a right-side drawer on both desktop and smaller layouts to save space in the sidebar.
- `App.tsx` was reorganized to fetch only when server-side inputs change, then reuse the current listings array for local transforms.
- Min/max buy/sell filters are now applied in `App.tsx` before the local spread/standard sort step so price-only changes can reuse the existing list.
- `MarketDetail` now has a local Refresh button in the detail header.
- The detail refresh is driven by local component state in `MarketDetail`, so it reloads the selected detail page and order history without retriggering the whole list fetch in `App.tsx`.
- The Market Detail summary cards now show `7-day trend` and `All time average` instead of the old history-start date cards.
- `7-day trend` is derived from the daily buy-now history series over the latest 7-day window, and `All time average` is derived from the all-orders dataset currently shown in detail view.
- The `All time average` card now also shows a signed `buy now vs avg` difference badge, colored by whether the current buy-now price is above or below the all-time average.
- The backend `/api/cards/averages` endpoint now removes outlier trade prices with an IQR-based robust-average calculation before returning list-view average prices, using a widened `3.0 * IQR` fence instead of the more aggressive standard `1.5 * IQR`.
- The market list can still sort by `Buy now vs avg`, but the temporary post-query min/max filters for that diff were removed to keep the filter section smaller.
- The market list now has an explicit asc/desc sort-direction icon button next to the sort dropdown, backed by a `sortDirection` query param and shared local sort helpers.
- 2026-04-21: The backend now stores robust all-time order averages in a persistent `market_card_averages` SQLite table instead of recomputing every average during `/api/cards/averages` page loads.
- `src/server/marketServer.ts` warms the average cache once if the table is empty, reads `/api/cards/averages` directly from the cache table, and refreshes each card's cached average after collection or on-demand detail refreshes insert new orders.
- 2026-04-21: `MarketDetail` now reads the selected card's all-time average through the cached average API instead of recomputing it from the long all-orders dataset.
- Future player/card average-price features should use the same `market_card_averages` table via the cached average endpoints (`/api/cards/averages` or `/api/cards/:uuid/average`) so list, detail, sorting, and any new average-price UI stay consistent.
- 2026-04-21: Fixed the initial market-list fetch guard in `App.tsx`; an empty URL with no `itemType`, `query`, or `rarity` now still performs the first server fetch instead of reusing the empty initial list.
- 2026-04-21: Added a URL-backed post-query `series` filter in the SearchPanel filter drawer. `App.tsx` derives available series options dynamically from the current fetched listing set and filters locally, so changing series does not trigger a new listing API fetch.
- Current local `market_cards` series values observed when adding the filter: `2nd Half Heroes`, `All-Star`, `Awards`, `Breakout`, `Contributor`, `Default`, `Egg Hunt`, `Last Ride`, `Live`, `New Threads`, `Postseason`, `Spotlight`, `Spring Breakout`, `St. Patrick's Day`, `Standout`, `Topps Now`, `Veteran`, and `World Baseball Classic`; future API values should appear automatically because the UI does not hard-code this list.
- 2026-04-22: Type changes now clear the post-query `series` filter, and `App.tsx` also drops stale series params when the newly fetched result set does not contain that series. This prevents `series=Live` from making non-player types like Equipment look empty because those item types currently return `series: Default`.
- 2026-04-22: The SearchPanel filter drawer button now shows the active post-query filter count in a small MUI badge instead of appending the count to the button text.
- 2026-04-22: The SearchPanel main filter row includes a visible `Clear all` action that resets pre-query filters (`query`, `itemType`, `rarity`) and post-query filters (`series`, min/max buy/sell, minimum spread) without changing sort settings.
- Reminder for UI/UX changes: consider the actual page layout and user workflow before choosing where controls live; make smart, reasonable placement and behavior decisions from the user's perspective rather than simply adding controls wherever the code is easiest.
- 2026-04-22: The sort dropdown now uses the app's effective default sort (`Overall` / `rank`) when no `sort` query param exists, and the control has a minimum width so it does not collapse before the user picks a sort.
- 2026-04-23: Sort and series select values are normalized before passing them to MUI Select controls. This avoids out-of-range select errors when URL params are missing, invalid, or differ only by case from dynamic options such as `World Baseball Classic`.
